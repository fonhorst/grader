### Методология проверки студенческого проекта "Реализация приложения на Apache Spark для распределенного обучения модели машинного обучения"

#### Предварительные требования
Перед началом проверки убедитесь в наличии:
- Кластера Kubernetes с доступными ресурсами для развертывания приложения.
- Установленных инструментов управления Kubernetes (kubectl, helm и др.).
- Конфигурации Apache Spark, поддерживающей динамическое выделение ресурсов.
- Средств мониторинга и логирования (например, Prometheus, Grafana, ELK-стек).
- Предопределённых тестовых данных для подготовки и обучения модели.
- Инструментов для тестирования распределенного обучения (например, OpenMPI).

---

### Зарезервированные имена объектов

| Имя                 | Тип объекта          | Описание                                                       |
|---------------------|----------------------|----------------------------------------------------------------|
| `data_preprocessing`| Spark Job            | Обработка и подготовка данных для обучения.                   |
| `model_training`    | Spark Job            | Распределенное обучение модели с использованием OpenMPI.       |
| `hyperparam_search` | Spark Job            | Подбор гиперпараметров модели параллельно.                     |
| `spark_cluster`     | Kubernetes StatefulSet | Кластер Apache Spark для выполнения заданий.                   |
| `monitoring_dashboard`| Grafana Dashboard    | Панель мониторинга метрик кластера и выполнения Spark Jobs.    |

---

### Этапы проверки

#### 1. Проверка инфраструктуры

1. **Проверка Kubernetes-кластера:**
   - Убедитесь, что кластер Kubernetes работает корректно и настроен для запуска Spark Jobs:
     ```bash
     kubectl get pods
     kubectl get services
     kubectl get statefulsets
     ```
   - Проверьте доступность Spark-кластера:
     ```bash
     kubectl get pods -l app=spark
     kubectl logs <spark-master-pod>
     ```

2. **Проверка Spark конфигурации:**
   - Убедитесь, что в конфигурации включено динамическое выделение ресурсов:
     ```bash
     kubectl exec -it <spark-master-pod> -- cat /opt/spark/conf/spark-defaults.conf
     ```
   - Проверьте настройки для параллельного выполнения задач.

---

#### 2. Проверка функциональности приложения

1. **Обработка данных:**
   - Запустите Job для подготовки данных:
     ```bash
     spark-submit --master k8s://<kubernetes-master-url> \
       --class com.example.DataPreprocessing \
       local:///opt/spark/jars/app.jar
     ```
   - Убедитесь, что данные корректно обработаны и сохранены в хранилище (например, HDFS, S3).

2. **Обучение модели:**
   - Запустите распределенное обучение модели:
     ```bash
     spark-submit --master k8s://<kubernetes-master-url> \
       --class com.example.ModelTraining \
       local:///opt/spark/jars/app.jar
     ```
   - Проверьте корректность выполнения и минимизацию операций shuffle.

3. **Подбор гиперпараметров:**
   - Запустите Job для подбора гиперпараметров:
     ```bash
     spark-submit --master k8s://<kubernetes-master-url> \
       --class com.example.HyperparamSearch \
       local:///opt/spark/jars/app.jar
     ```
   - Убедитесь, что результаты подбора гиперпараметров сохранены в указанное место.

---

#### 3. Проверка метрик и мониторинга

1. **Мониторинг выполнения Jobs:**
   - Проверьте панели мониторинга Grafana для анализа метрик выполнения Spark Jobs:
     - Использование CPU и RAM.
     - Количество операций shuffle.
     - Распределение нагрузки между executors.

2. **Анализ логов:**
   - Используйте ELK-стек или встроенные средства Spark для анализа логов:
     ```bash
     kubectl logs <spark-executor-pod>
     ```

---

#### 4. Тестирование производительности

1. **Генерация нагрузки:**
   - Используйте скрипт для создания большого объема данных и запуска нескольких Jobs параллельно.

2. **Измерение метрик:**
   - Время выполнения Jobs.
   - Количество выполненных задач параллельно.
   - Уровень ошибок.

---

#### 5. Проверка отказоустойчивости

1. **Симуляция отказа:**
   - Остановите один из Spark Executors и проверьте, что Job завершился успешно:
     ```bash
     kubectl delete pod <spark-executor-pod>
     ```

2. **Проверка восстановления:**
   - Убедитесь, что система корректно перераспределяет задачи между оставшимися executors.
