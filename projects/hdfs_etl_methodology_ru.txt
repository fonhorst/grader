# Методология проверки проекта: ETL пайплайн для HDFS

## Предварительные требования
Перед началом проверки убедитесь в наличии следующих ресурсов:
1. **Доступ к кластеру Kubernetes**: Проверьте, что пайплайн развернут корректно, используя контейнеры.
2. **Инструменты для работы с HDFS**: Установлены `hdfs dfs` или Python-библиотеки (`pydoop`, `hdfs`).
3. **Набор тестовых данных**: Предопределенные CSV-файлы для проверки функциональности.
4. **Инструменты мониторинга**: Grafana и Prometheus для сбора метрик производительности.
5. **Логирование**: Убедитесь, что используются инструменты для проверки логов (`ELK Stack` или аналогичные).

## Зарезервированные имена объектов

| Имя                | Тип объекта       | Описание                                       |
|--------------------|-------------------|-----------------------------------------------|
| `input_data`        | Директория HDFS   | Входные данные для пайплайна.                 |
| `processed_data`    | Директория HDFS   | Обработанные данные после ETL.               |
| `etl_pipeline`      | Kubernetes Pod    | Основной компонент обработки данных.          |
| `file_watcher`      | Kubernetes Pod    | Компонент мониторинга новых файлов в HDFS.    |
| `etl_logs`          | Elasticsearch Index | Логи ETL пайплайна.                          |
| `dashboards`        | Grafana Dashboard | Мониторинг обработки файлов и производительности. |

---

## Этапы проверки

### 1. Проверка наличия требуемых объектов
#### Kubernetes
1. Убедитесь, что все pods и сервисы активны:
   ```bash
   kubectl get pods
   kubectl get services
   ```
2. Проверьте, что запущены компоненты `etl_pipeline` и `file_watcher`.

#### HDFS
1. Проверьте, что директории `input_data` и `processed_data` существуют:
   ```bash
   hdfs dfs -ls /input_data
   hdfs dfs -ls /processed_data
   ```

2. Убедитесь, что права доступа к директориям корректны:
   ```bash
   hdfs dfs -ls -R /input_data
   ```

---

### 2. Проверка функциональных возможностей
#### Загрузка данных в HDFS
1. Скопируйте тестовые файлы в директорию `input_data`:
   ```bash
   hdfs dfs -put test_data.csv /input_data/
   ```
2. Проверьте, что файл успешно появился:
   ```bash
   hdfs dfs -ls /input_data
   ```

#### Обработка данных
1. Убедитесь, что новый файл был обнаружен `file_watcher` (проверьте логи):
   ```bash
   kubectl logs <file_watcher_pod>
   ```

2. Проверьте содержимое обработанных данных в директории `processed_data`:
   ```bash
   hdfs dfs -cat /processed_data/processed_test_data.csv
   ```

3. Проверьте корректность выполнения ETL:
   - Убедитесь, что:
     - Транзакции с `status = 'failed'` отсутствуют.
     - Все суммы сконвертированы в USD.

---

### 3. Проверка формальных ограничений
1. **Контейнеризация**:
   - Проверьте, что проект развернут с использованием Docker/Kubernetes:
     ```bash
     kubectl get deployments
     kubectl get pods
     ```

2. **Логи**:
   - Убедитесь, что все логи пишутся в Elasticsearch:
     ```bash
     curl -X GET "http://<elasticsearch_url>/etl_logs/_search"
     ```

3. **Шардинг и репликация**:
   - Проверьте наличие как минимум трех реплик для компонентов:
     ```bash
     kubectl get pods -o wide
     ```

---

### 4. Проверка отказоустойчивости
1. Остановите один из pods:
   ```bash
   kubectl delete pod <etl_pipeline_pod>
   ```
2. Убедитесь, что система продолжает обработку данных после восстановления pods.

---

### 5. Тестирование нагрузки
#### Генерация нагрузки
1. Загрузите множество файлов в `input_data`:
   ```bash
   for i in {1..100}; do
       hdfs dfs -put test_data_$i.csv /input_data/
   done
   ```

#### Мониторинг нагрузки
1. Проверьте задержку обработки данных в Grafana.
2. Сравните фактическое время обработки с допустимым (например, не более 1 минуты на файл).
