
Представьте, что у нас есть веб-платформа для онлайн-продаж. Пользователи могут посещать и просматривать различные страницы на сайте платформы и выполнять различные операции, в основном: бронирование, покупка, возврат, отмена бронирования. Платформа реализована как набор микросервисов, и для выполнения финансовых транзакций она может взаимодействовать с внешними сервисами (которые находятся вне нашего контроля), в зависимости от предпочтений пользователя и поставщика для оплаты. 
Несколько микросервисов участвуют в обработке каждой операции, поэтому гарантируется, что у каждой есть уникальный идентификатор, который сохраняется во всех микросервисах. Пользователи могут допускать ошибки при бронировании или покупке, внешние сервисы могут быть временно недоступны или перегружены для обработки запросов на оплату. Программное обеспечение платформы и внешние сервисы также могут содержать ошибки, которые приводят к различным сбоям.
Этот набор микросервисов постоянно генерирует логи, метрики и записи в базе данных. Бизнес хочет, чтобы эти логи и метрики собирались для расчета различных статистических данных и проверки проблем с производительностью, ошибок и аномалий. Вам необходимо построить систему, которая может обслуживать аналитические запросы, поднимать тревоги при обнаружении аномалий и заполнять панели мониторинга, посвященные мониторингу (не в реальном времени, но близко к этому).
Данные за последний месяц должны храниться в "горячем" хранилище для быстрого оперативного доступа, а старые данные должны быть перемещены в архив на S3. Тревоги должны срабатывать мгновенно или в течение нескольких минут, если событие сложное (например, несколько неудачных попыток для нескольких пользователей с одним и тем же поставщиком платежей).
Чтобы облегчить вашу задачу, уже существует инфраструктура для сбора данных из вышеперечисленных источников, которая записывает собранные данные в систему очередей сообщений. Таким образом, вам нужно только интегрироваться с этой системой очередей, а не со всеми микросервисами.

Примеры возможных пользовательских запросов, которые необходимо удовлетворить:
1. Получить все события по разным микросервисам, связанным с одним и тем же ID действия (например, трассировка запросов).
2. Получить события по определенному уровню событий (debug/info/warn/error) и их типу для одного или нескольких микросервисов за определенный интервал.
3. Количество одновременно просматривающих / покупающих пользователей.
4. Бизнес-метрики (для финансовой отчетности и обнаружения аномалий для поднятия тревог):
- количество транзакций за интервал (15 минут / 1 час / 3 часа / 1 день);
- просмотры страниц за интервал (15 минут / 1 час / 3 часа / 1 день);
- количество повторных попыток с успешным или неуспешным исходом (в конечном итоге).
5. Производительность:
время выполнения операций (мин, макс, среднее, перцентили);
использование CPU / RAM за интервал одновременно с количеством пользователей.
6. Аномалии:
множество одинаковых операций;
покупка и возврат и т.д.

Требования к системе:
1. Шардинг (как минимум 3 сервера).
2. Репликация.
3. Чтение из системы очередей сообщений (Kafka, Redis).
4. Входящие данные должны обрабатываться с помощью решения для потоковой обработки данных (например, Spark Streaming, но можно предложить альтернативу), чтобы поднимать тревоги при обнаружении аномалий (применимо только для коротких периодов времени: десятки секунд или несколько минут).
5. Архивация обязательна.
6. Как минимум одна панель мониторинга обязательна.
7. Генератор(-ы) данных и процедура загрузки обязательны (можно использовать библиотеки для генерации фальшивых логов, например https://github.com/mingrammer/flog).
8. Генераторы нагрузки для запросов должны быть реализованы. Хранилище должно уметь одновременно вставлять данные и обрабатывать запросы select.
9. Тестовые сценарии должны быть реализованы как демонстрация решения.
10. Развертывание на "голом железе" запрещено. Разверните хранилище с репликами, очередями, генераторами, запросчиками и другими модулями, используя Kubernetes, Docker (см. Kubernetes StatefulSet / Deployment / Job и т.д.).
