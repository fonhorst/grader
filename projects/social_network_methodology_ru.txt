
# Методология проверки корректности студенческих проектов в курсе «Продвинутые технологии больших данных»

## Предварительные требования
Для проверки решений студентов должны быть доступны следующие инструменты и настройки:
1. Кластер Kubernetes, где развернуто решение.
2. Доступ ко всем необходимым сервисам, базам данных (ClickHouse, ArangoDB, Elasticsearch) и инструментам мониторинга, как указано в требованиях проекта.
3. Набор заранее определенных функциональных и нефункциональных требований, основанных на описании проекта.
4. Инструменты для тестирования нагрузок (например, Apache JMeter или собственные скрипты на Python).
5. Зарезервированные имена объектов для проверки формальной структуры (таблицы, коллекции, сервисы и т.д.).

## Предопределенные зарезервированные имена объектов

| Имя        | Тип объекта     | Описание                                          |
|-------------|-----------------|--------------------------------------------------|
| profiles    | Коллекция/Таблица | Хранит информацию о профилях пользователей (имя, город и т.д.). |
| streams     | Сервис          | Kafka-сервис для обработки потоков данных.       |
| clickhouse  | База данных     | Хранилище для актуальных и исторических данных.   |
| monitoring  | Панель мониторинга/Сервис | Панели для мониторинга использования CPU, RAM и ввода-вывода. |
| dm_lifecycle | Витрина данных  | Жизненный цикл витрины данных для обработки специфичных данных. |

## Этапы проверки корректности

### 1. Проверка наличия требуемых объектов
Убедитесь, что решение студента содержит все необходимые компоненты, базы данных и сервисы, указанные в списке предопределенных объектов.

- **Пример SQL-запроса (для ClickHouse):**
    ```sql
    SHOW TABLES;
    ```

- **Пример NoSQL-запроса (для ArangoDB):**
    ```sql
    FOR doc IN profiles RETURN doc
    ```

- **Пример веб-запроса (для конечных точек сервисов):**
    ```bash
    curl http://<адрес-сервиса>/healthcheck
    ```

### 2. Проверка функциональных возможностей
Убедитесь, что решение выполняет ожидаемое собирание данных, их обновление и мониторинг в соответствии с требованиями:

1. **Загрузка данных:**
    Проверьте, что решение корректно загружает данные из потоков Kafka, не допуская дублирования записей и потери данных.

    - **Запрос для проверки дублирования в ClickHouse:**
        ```sql
        SELECT COUNT(*), user_id FROM profiles GROUP BY user_id HAVING COUNT(*) > 1;
        ```

    - **Проверка топика Kafka:**
        ```bash
        kafka-topics --list --zookeeper <zookeeper_url>
        ```

2. **Обновление и поддержка данных:**
    Убедитесь, что данные профилей пользователей могут обновляться и изменения отображаются в базе данных.

    - **SQL-запрос для проверки недавних обновлений в ClickHouse:**
        ```sql
        SELECT * FROM profiles WHERE last_updated > NOW() - INTERVAL 1 DAY;
        ```

3. **Полнотекстовый поиск:**
    Убедитесь, что Elasticsearch работает корректно и полнотекстовые запросы выполняются правильно.

    - **Запрос к Elasticsearch:**
        ```bash
        curl -X GET "http://<elasticsearch_url>/profiles/_search?q=city:Berlin"
        ```

4. **Панели мониторинга:**
    Проверьте наличие и функциональность панелей мониторинга для сервисов и системных ресурсов.

### 3. Проверка формальных ограничений
Убедитесь, что формальные ограничения, указанные в проекте (такие как развертывание в контейнерах, запрет на развертывание на «голом железе»), соблюдены.

- **Команда для проверки контейнеров Kubernetes:**
    ```bash
    kubectl get pods -o wide
    ```

- **Запрос для проверки лимитов ресурсов Kubernetes:**
    ```bash
    kubectl describe pod <pod_name> | grep "Limits"
    ```

### 4. Проверка отказоустойчивости
Убедитесь, что система является отказоустойчивой, как указано в требованиях. Решение должно корректно обрабатывать некорректное извлечение данных, сбои в системе и восстанавливаться после них.

- **Тестирование отказоустойчивости в Kafka:**
    Остановите один из брокеров Kafka и проверьте, продолжает ли система загрузку данных из потоков.

    - **Команда для остановки брокера Kafka:**
        ```bash
        kafka-server-stop.sh <broker_id>
        ```

    - **Проверьте сохранение данных после остановки брокера Kafka:**
        ```bash
        kafka-console-consumer.sh --bootstrap-server <kafka_broker> --topic <topic_name> --from-beginning
        ```

### 5. Тестирование нагрузки
Этот раздел посвящен проверке нефункциональных возможностей под нагрузкой. Ниже приводится подробное описание процесса тестирования нагрузки:

#### Генерация данных
1. **Частота запросов:** Генерация данных для 100 000 профилей пользователей каждые 10 секунд.
2. **Тип данных:** Случайные профили с именем, фамилией, городом и адресом электронной почты.
3. **Объем:** Решение должно обрабатывать до 1 миллиона запросов в минуту.

#### Тестирование загрузки данных
- **Запрос для мониторинга скорости загрузки потока Kafka:**
    ```bash
    kafka-consumer-groups --describe --group <group_id>
    ```

#### Измерение пропускной способности и задержек
- **Команда для измерения сетевого ввода-вывода при загрузке данных:**
    ```bash
    kubectl top pods
    ```

- **Скрипт для генерации нагрузки и мониторинга времени ответа системы:**
    ```python
    import requests
    for i in range(100000):
        response = requests.post('http://<адрес-сервиса>/ingest', json={"name": "John", "city": "Berlin"})
        print(response.elapsed.total_seconds())
    ```

#### Тестирование производительности запросов данных
1. Выполните сложные SQL-запросы под высокой нагрузкой, чтобы измерить время отклика.

    - **Пример SQL-запроса:**
        ```sql
        SELECT city, COUNT(*) FROM profiles GROUP BY city;
        ```

    Измерьте время отклика и проверьте, укладывается ли оно в допустимые пределы (менее 2 секунд для запросов под нагрузкой).

### Заключение
Эта методология обеспечивает, что решения студентов соответствуют функциональным, нефункциональным и формальным требованиям, а также предоставляет набор тестов для проверки развертывания в кластере Kubernetes. Методология может быть реализована как автоматизированные проверки кода для повышения эффективности.
