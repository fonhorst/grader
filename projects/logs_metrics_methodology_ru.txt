
# Методология проверки студенческого проекта

## Предварительные требования
Перед началом проверки убедитесь в наличии следующих ресурсов:
- Доступ к кластеру Kubernetes, где развернуто решение.
- Установленные инструменты CLI для Kubernetes (kubectl, helm и т.д.).
- Учетные данные для доступа к кластеру и соответствующим сервисам (Elasticsearch, ClickHouse, ArangoDB, Kafka).
- Предопределенные тестовые данные и инструменты для генерации данных.
- Инструменты мониторинга и оповещений (Prometheus, Grafana) для тестов нагрузки и производительности.

## Зарезервированные имена требуемых объектов
Следующая таблица содержит зарезервированные имена для объектов кластера, таблиц и столбцов.

| Имя             | Тип объекта      | Описание                                                              |
|-----------------|------------------|-----------------------------------------------------------------------|
| `log_events`    | Таблица ClickHouse | Хранит журналы событий для действий микросервисов.                     |
| `metrics_data`  | Таблица ClickHouse | Содержит метрики производительности, CPU/RAM и количества одновременных пользователей. |
| `transactions`  | Коллекция ArangoDB | Содержит данные транзакций для всех сервисов.                          |
| `archive_data`  | Корзина S3        | Хранит старые данные, перемещенные из горячего хранилища.              |
| `event_stream`  | Топик Kafka       | Хранит журналы событий в реальном времени, поступающие от микросервисов.|
| `alerts`        | Индекс Elasticsearch | Хранит сгенерированные оповещения для обнаружения аномалий.            |
| `dashboards`    | Панели Grafana    | Мониторинг системных метрик, бизнес-метрик и аномалий.                 |

## 1. Проверка наличия требуемых объектов
1. **Проверка кластера Kubernetes:**
   - Убедитесь, что требуемые pod-ы, сервисы и StatefulSets/Deployments работают.
     ```bash
     kubectl get pods
     kubectl get services
     kubectl get statefulsets
     ```
   - Проверьте работу сервисов Kafka, ArangoDB, ClickHouse, Elasticsearch и Prometheus.
     ```bash
     kubectl get pods -l app=kafka
     kubectl get pods -l app=clickhouse
     kubectl get pods -l app=elasticsearch
     ```

2. **Проверка баз данных и таблиц:**
   - Убедитесь, что таблицы `log_events` и `metrics_data` существуют в ClickHouse.
     ```sql
     SHOW TABLES FROM default;
     DESCRIBE TABLE log_events;
     DESCRIBE TABLE metrics_data;
     ```

   - Убедитесь, что коллекция `transactions` существует в ArangoDB.
     ```javascript
     db._collections();
     db.transactions.exists();
     ```

3. **Проверка топиков Kafka:**
   - Убедитесь, что топик Kafka `event_stream` присутствует и получает сообщения.
     ```bash
     kafka-topics.sh --list --zookeeper <zookeeper-host>
     kafka-console-consumer.sh --topic event_stream --bootstrap-server <broker-host>
     ```

## 2. Проверка функциональных возможностей
1. **Агрегация журналов:**
   - Проверьте, что журналы корректно агрегируются, сделав запрос к `log_events` в ClickHouse:
     ```sql
     SELECT * FROM log_events WHERE action_id = '<some_action_id>';
     ```
   - Убедитесь, что журналы записываются в режиме, близком к реальному времени.

2. **Запрос метрик:**
   - Проверьте метрики, такие как использование CPU/RAM и количество одновременных пользователей:
     ```sql
     SELECT cpu_usage, ram_usage, concurrent_users 
     FROM metrics_data 
     WHERE timestamp BETWEEN '<start>' AND '<end>';
     ```

3. **Бизнес-метрики:**
   - Проверьте, может ли система получать количество транзакций и просмотров страниц за интервал:
     ```sql
     SELECT COUNT(*) AS transactions_count, SUM(page_views) 
     FROM transactions 
     WHERE timestamp BETWEEN '<start>' AND '<end>';
     ```

4. **Обнаружение аномалий:**
   - Проверьте логику обнаружения аномалий, сделав запрос к оповещениям в Elasticsearch:
     ```json
     GET /alerts/_search
     {
       "query": {
         "match": {
           "anomaly_type": "multitude_of_same_operations"
         }
       }
     }
     ```

5. **Архивирование:**
   - Проверьте, что старые данные перемещаются на S3 через месяц:
     ```bash
     aws s3 ls s3://<bucket-name>/archive_data/
     ```

## 3. Проверка формальных ограничений
1. **Шардинг и репликация:**
   - Убедитесь, что в базах данных и Kafka включены шардинг и репликация на как минимум 3 узлах.
     ```bash
     kubectl exec -it <clickhouse-pod> -- clickhouse-client --query "SHOW CLUSTER;"
     kafka-topics.sh --describe --topic event_stream --zookeeper <zookeeper-host>
     ```

2. **Развертывание в Kubernetes:**
   - Проверьте соблюдение ограничений развертывания (без "голого железа"):
     ```bash
     kubectl get nodes
     ```

## 4. Проверка отказоустойчивости
1. **Устойчивость микросервисов:**
   - Выполните контролируемый отказ одного из микросервисов и посмотрите, как ведет себя система. Проверьте, выполняются ли повторные попытки после восстановления.
     ```bash
     kubectl delete pod <microservice-pod>
     ```

2. **Обработка сбоев внешних сервисов:**
   - Проверьте, корректно ли система обрабатывает сбои внешних сервисов (например, поставщика платежей):
     - Симулируйте отказ внешнего сервиса и проверьте повторные попытки:
     ```bash
     kafka-console-producer.sh --topic event_stream --bootstrap-server <broker-host> 
     ```

## 5. Тестирование нагрузки
### Описание тестов
1. **Генерация нагрузки:**
   - Используйте генераторы нагрузки для создания журналов, транзакций и операций пользователей на разных интервалах (15 минут, 1 час).
   - Примеры запросов:
     ```bash
     flog -t apache_combined -n 100000 --start-time '1/Apr/2024:10:00:00'
     ```

2. **Частота и объем:**
   - Журналы: 10 000 журналов в минуту.
   - Транзакции: 5 000 транзакционных запросов в минуту.
   - Запросы должны выполняться одновременно, чтобы убедиться, что система справляется с одновременным чтением/записью.

3. **Измерения:**
   - Измерьте:
     - Использование CPU и RAM за интервал.
     - Время отклика (мин, макс, среднее).
     - Уровень ошибок.
     - Задержку обработки данных.

4. **Мониторинг:**
   - Используйте Grafana для проверки:
     - Нагрузки на систему.
     - Запусков тревог (аномалии, повторные попытки).
     - Обновления панелей мониторинга каждую минуту.
