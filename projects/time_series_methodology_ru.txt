
# Методология проверки корректности выполнения студентами решений в области больших данных

Эта методология описывает пошаговый процесс проверки корректности развернутого студентами решения для больших данных в кластере Kubernetes. Включает проверки функциональных, нефункциональных возможностей, а также формальные проверки, тестирование нагрузки и другие важные аспекты.

## Предварительные требования
Для начала процесса проверки убедитесь, что у вас есть:
- Доступ к кластеру Kubernetes, где развернуто решение.
- Инструменты для взаимодействия с базами данных SQL/NoSQL (например, клиент ClickHouse) и HTTP-клиенты для веб-запросов.
- Механизмы генерации и загрузки данных, реализованные в проекте (например, Kafka для загрузки).
- Набор предопределенных тестовых сценариев и инструментов сбора метрик (например, Grafana для мониторинга производительности).

## Зарезервированные имена объектов
| Имя                | Тип объекта      | Описание                                                |
|--------------------|------------------|---------------------------------------------------------|
| `sensor_data_raw`   | Таблица ClickHouse| Хранит "сырые" данные от сенсоров.                       |
| `sensor_lens`       | Таблица ClickHouse| Хранит агрегированные данные для пользовательского интерфейса.|
| `data_ingestor`     | Kubernetes Job   | Обрабатывает загрузку данных в ClickHouse.               |
| `workload_generator`| Kubernetes Job   | Генерирует симулированные нагрузки для тестирования.     |
| `request_handler`   | Kubernetes Pod   | Принимает и обрабатывает запросы на данные.              |
| `kafka_topic_sensors`| Топик Kafka     | Промежуточное хранилище данных сенсоров перед загрузкой. |

## Пошаговые проверки

### 1. Проверка наличия необходимых объектов
Убедитесь, что все требуемые объекты развернуты и правильно настроены.

#### Кластер Kubernetes
- Выполните команду `kubectl get pods,services,jobs`, чтобы убедиться в наличии `data_ingestor`, `workload_generator` и `request_handler`.

#### Таблицы ClickHouse
- Проверьте таблицы ClickHouse:
  ```sql
  SHOW TABLES FROM default;
  ```

Ожидаемый результат должен включать:
- `sensor_data_raw`
- `sensor_lens`
